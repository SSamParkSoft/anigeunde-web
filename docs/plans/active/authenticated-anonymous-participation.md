# 로그인된 익명 참여

- 상태: `ACTIVE`
- 최종 갱신일: `2026-08-18`
- 대상: Next.js, FastAPI, OAuth, 참여·댓글 API
- 기준 설계: [`anigeunde-service-design.md` 4장·12장·14.5절](../../../anigeunde-service-design.md)

## 1. 목표

쟁점과 공개 의견은 로그인 없이 읽을 수 있게 하되, 여론조작 방지와 민감정보 동의 기록을 위해 실제 집계·작성 행위는 로그인 계정에만 허용한다. 로그인은 실명을 공개하기 위한 절차가 아니며, 다른 이용자에게는 소셜 계정 정보 대신 서비스 닉네임만 표시한다.

## 2. 확정된 제품 결정

| 기능 | 비로그인 | 로그인 |
|---|---|---|
| 쟁점·참고자료 열람 | 허용 | 허용 |
| 공개 의견·댓글 열람 | 허용 | 허용 |
| 선택지 누르기 | 임시 선택만 허용 | 확정 가능 |
| 참여 결과 반영·열람 | 불가 | 입장 확정 후 가능 |
| 의견·댓글·반응 | 불가 | 입장 확정 후 가능 |

- OAuth 공급자는 Google과 Kakao 두 가지로 시작한다.
- 로그인 완료 전 선택은 서버 집계에 포함하지 않는다.
- 로그인과 필수 동의를 완료하면 임시 선택을 같은 쟁점에 자동 확정한다.
- 화면에는 닉네임과 이용자가 공개하기로 한 쟁점별 입장만 표시한다.
- 이메일, 소셜 제공자, 소셜 프로필과 내부 사용자 ID는 다른 이용자에게 공개하지 않는다.
- 참여 수는 실제 사람 수가 아니라 유효한 회원 계정 수이며 과학적 여론조사가 아님을 항상 표시한다.
- MVP 가입은 만 14세 이상으로 제한한다. 만 14세 미만 가입과 법정대리인 동의 기능은 제공하지 않는다.

## 3. 로그인·동의 흐름

```text
비로그인 이용자가 선택지를 누름
  → 쟁점 ID와 선택지 ID를 탭 단위로 임시 보관
  → 로그인 안내 표시
  → 만 14세 이상 확인
  → 이용약관·개인정보 처리 필수 동의
  → 정치적 견해 등 민감정보 처리 별도 필수 동의
  → Google 또는 Kakao OAuth
  → 서버 세션 생성
  → 동의 버전과 시각 저장
  → 임시 선택 확정
  → 집계 결과 공개
```

로그인 안내에는 다음을 명확히 표시한다.

- 로그인은 중복 참여와 도배를 줄이기 위한 장치다.
- 소셜 계정과 이메일은 다른 이용자에게 공개되지 않는다.
- 서비스에는 익명 닉네임만 표시된다.
- 선택을 확정하면 정치적 견해에 해당할 수 있는 정보가 처리된다.

## 4. 서버 권한 계약

- 공개 `GET` API는 인증 없이 호출할 수 있다.
- 비로그인 쟁점 상세 응답은 `my_position_id`와 결과 분포를 반환하지 않는다.
- 입장, 의견, 댓글, 반응의 모든 상태 변경 API는 유효한 서버 세션과 CSRF 검증을 요구한다.
- `X-Viewer-ID` 데모 헤더는 로컬 개발에서만 허용하고 배포 환경에서는 거부한다.
- `positions`는 `(issue_id, user_id)` 유일 제약으로 계정당 활성 입장을 하나만 허용한다.
- Google 계정과 Kakao 계정의 자동 병합은 하지 않는다. 이상 참여 탐지와 집계 제외 기능을 별도로 둔다.

## 5. 익명성과 운영자 접근

- 익명은 다른 이용자에게 신원 정보가 보이지 않는다는 의미이며, 불법행위까지 추적 불가능하다는 의미가 아니다.
- 일반 관리자 화면에서는 소셜 식별자와 개별 정치적 입장을 함께 조회할 수 없게 한다.
- 신고·부정 이용 조사에 필요한 접근은 최소 역할로 제한하고 감사 로그를 남긴다.
- 개별 입장 값과 댓글 원문을 외부 분석 도구나 일반 애플리케이션 로그에 전송하지 않는다.

## 6. 현재 데모와 실제 구현의 경계

현재 웹은 로그인 요구 화면과 임시 선택 UX를 목업으로 검증한다. Google·Kakao 버튼은 실제 OAuth가 연결되기 전에는 데모 사용자 세션으로만 동작하며, 이를 화면에 표시한다. 현재 API의 고정 `X-Viewer-ID`는 제품 인증으로 간주하지 않는다.

## 7. 구현 순서

1. 로그인 요구·필수 동의·임시 선택 UI 검증
2. 사용자, 외부 계정, 동의 이력, 세션 테이블과 마이그레이션
3. Google OAuth와 Kakao OAuth 콜백
4. HttpOnly 세션, CSRF, Origin·CORS 검증
5. 공개 조회와 인증 상태 조회 API 분리
6. 입장·댓글·반응 API에서 데모 헤더 제거와 세션 권한 적용
7. 닉네임 설정, 로그아웃, 세션 목록과 계정 탈퇴
8. 중복·자동화 참여 탐지, 집계 제외와 운영 감사 로그

## 8. 완료 기준

- [ ] 비회원이 쟁점과 공개 의견을 읽을 수 있다.
- [ ] 비회원의 선택은 로그인 전 서버와 집계에 저장되지 않는다.
- [ ] 로그인 완료 후 같은 선택이 한 번만 확정된다.
- [ ] 결과 분포는 입장 확정 전 API 응답과 화면에서 모두 숨겨진다.
- [ ] 의견·댓글·반응 API가 비로그인 요청을 `401`로 거부한다.
- [ ] 만 14세 이상, 일반 필수 동의, 민감정보 별도 동의와 버전을 서버가 검증·저장한다.
- [ ] Google·Kakao 계정 정보가 공개 프로필과 댓글 API에 포함되지 않는다.
- [ ] 세션 쿠키, CSRF, OAuth state·PKCE·nonce 보안 테스트가 통과한다.
- [ ] 계정 탈퇴와 동의 철회 시 데이터 삭제·익명화 절차가 동작한다.
- [ ] 배포 환경에서 `X-Viewer-ID` 데모 인증이 작동하지 않는다.
