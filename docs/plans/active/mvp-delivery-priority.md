# MVP 출시 우선순위와 검증 범위

- 상태: `ACTIVE`
- 최종 갱신일: 2026-08-19
- 목적: 최소 기능 제품을 빠르게 출시하기 위한 구현 순서와 테스트 범위를 고정한다.

## 결정

현재 최우선 목표는 완전한 테스트 커버리지가 아니라 실제 사용 가능한 MVP를 빠르게 배포하고 운영 피드백을 받는 것이다.

1. 다음 구현 작업은 CI/CD 구축을 가장 먼저 진행한다.
2. 자동 테스트는 장애, 데이터 훼손, 중복 참여, 인증 우회처럼 출시를 막아야 하는 핵심 위험만 작성한다.
3. 화면 단위 테스트, 스냅샷 테스트, 광범위한 브라우저 조합, 모든 예외 입력 테스트는 MVP 출시 이후로 미룬다.
4. 테스트를 생략했다는 이유로 lint, 타입 검사, 프로덕션 빌드 검증까지 생략하지 않는다.
5. 운영 중 실제로 발생한 회귀 버그에는 재현 테스트를 추가한다.

## 1순위: CI/CD

CI/CD는 기능 개발보다 먼저 적용한다. 최소 파이프라인은 다음을 만족해야 한다.

- Pull Request와 `main` 반영 전에 웹 lint, TypeScript 검사와 프로덕션 빌드를 실행한다.
- API는 Ruff 검사와 핵심 테스트만 실행한다.
- 검증 실패 시 배포하지 않는다.
- 프론트엔드와 API 배포 환경 및 비밀값을 분리한다.
- 배포 결과와 실패 원인을 확인할 수 있는 로그를 남긴다.
- 초기에는 수동 승인 배포를 허용하되, 동일한 명령과 절차로 반복 가능해야 한다.

## MVP에서 반드시 검증할 항목

다음 항목은 장애 또는 여론 조작 위험과 직접 연결되므로 생략하지 않는다.

- 웹 프로덕션 빌드가 성공하고 주요 페이지가 렌더링되는지 확인
- API live/ready 상태 확인
- 비회원은 쟁점과 의견을 읽을 수 있지만 의견 작성과 결과 반영은 할 수 없는지 확인
- 인증된 계정의 투표가 쟁점별 한 번만 집계되고 변경 시 중복 누적되지 않는지 확인
- 의견, 댓글, 좋아요와 싫어요의 핵심 쓰기 흐름 확인
- 관리자만 쟁점을 최종 발행할 수 있는지 확인
- DB 마이그레이션 적용 실패 시 배포가 중단되는지 확인

## MVP 이후로 미루는 테스트

- 모든 UI 컴포넌트의 단위 테스트
- CSS 스냅샷과 전면적인 시각 회귀 테스트
- 모든 브라우저와 기기 조합의 자동화 테스트
- 비핵심 폼 입력값의 전체 경계값 조합
- 대규모 부하, 장시간 안정성과 장애 복구 훈련
- 관리자 화면의 비핵심 편의 기능 테스트

## 완료 기준

- 저장소에 CI 워크플로가 존재하고 Pull Request에서 자동 실행된다.
- 프론트엔드와 API의 반복 가능한 배포 절차가 저장소에 문서화되어 있다.
- 위의 필수 검증 항목이 자동 테스트 또는 배포 전 smoke test로 실행된다.
- 생략한 테스트가 출시 완료를 의미하지 않으며 MVP 이후 작업으로 남아 있음을 문서에서 확인할 수 있다.
